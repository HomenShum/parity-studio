# Self-dogfood — proof the platform works on itself

This page documents how Parity Studio v0.0.2's UI shell was built. It is not generated by the platform inside this repo (the platform's frontend isn't wired to its own backend yet), but the code in `src/components/*` and the CSS in `src/styles.css` were emitted by the same offline pipeline that the platform implements server-side. The same boolean rubric scored both the BEFORE-swap and AFTER-swap renderings.

The intent: prove that a sketch + a brief can become a verified, componentized, coding-agent-ready bundle — and that the bundle can be the actual production UI, not a side artifact.

## Pipeline used

```
prompt brief                         (parity-studio-shell.txt, hand-written)
     |
     v
gpt-image-2                          source.png (1536x1024 mockup)
     |
     v
claude-opus-4-1 (vision)             ui_kit/parity-studio/{index.html, components/*.tsx, tokens.css, manifest.json, README.md}
     |
     v
Playwright headless                  rendered.png (1440x900 of the emitted ui_kit)
     |
     v
claude-sonnet-4-5 (visual judge)     12-check boolean rubric -> parityScore = passCount / totalChecks
```

All five stages are also implemented in `convex/generation.ts` + `convex/lib/piAi.ts` + `convex/lib/parityChecker.ts`. The offline runner in `scripts/career/poc-headless-pipeline/` is the same shape, exercised end-to-end.

## BEFORE pass — generate from a brief

Input: `inputs/prompts/parity-studio-shell.txt` (the prompt described the 4-zone layout, warm-dark palette, terracotta accent, Manrope + JetBrains Mono fonts, etc. — the kind of brief a designer would write).

| Stage | Model | Latency | Cost |
|---|---|---:|---:|
| Source mockup | gpt-image-2 (1536x1024 high) | 81 s | $0.09 (cached on retry; original BEFORE pass used gpt-image-1, now upgraded) |
| Decompose | claude-opus-4-1 | 85 s | $0.40 |
| Render | Playwright chromium | 1.3 s | $0.00 |
| Judge | claude-sonnet-4-5 | 18 s | $0.025 |
| **Total** | | **~104 s** | **$0.43** |

Result:
- **parityScore = 1.00**, status = `verified`, 12/12 checks passed (one iter, threshold 0.85)
- Judge summary: "The candidate successfully reproduces the source design with all major layout regions, color palette, typography hierarchy, and component structures matching."

Honest non-claim: the visual judge missed one real artifact in the emitted code — the model tokenized "Hand off to Claude Code" as "Hand off to Claude C&b" in `tools-item` text. The judge's content check passed because no specific text was required; but the deterministic text-coverage check in `convex/lib/parityChecker.ts` would have flagged "code" missing from the rendered visible text. This is exactly why we have BOTH a deterministic verifier AND a visual judge — they catch different classes of drift.

The `C&b` was corrected to `Code` in `src/components/ActionSidebar.tsx` with a comment block citing the provenance.

## The swap

`src/styles.css` was replaced with the platform's emitted CSS verbatim (with three honest post-copy edits called out in the file header: Manrope/JetBrains Mono fonts to match the brief's typography, `:focus-visible` outlines for keyboard a11y per `.claude/rules/reexamine_a11y`, and a `prefers-reduced-motion` guard).

The five React components (`TopBar`, `InputBar`, `FilesPanel`, `PreviewPane`, `ActionSidebar`) were rewritten to match the platform-emitted DOM hierarchy and class names exactly. Interactive handlers (file upload, cmd+enter run, viewport tab toggle) were added on top of the platform's static structure.

`pnpm typecheck` clean. `pnpm test` passes 4/4 (parity checker including the CodeQL `js/bad-tag-filter` regression). `pnpm build` produces a clean dist (266 kB JS, 7 kB CSS, gzipped 81 + 2 kB).

## AFTER pass — re-decompose the live UI

Input: a Playwright screenshot of the actual Vite-built `dist/` running at 1440x900 (`runs/after-source.png`). This is the recursive test — what does the platform see when it looks at its own production UI?

| Stage | Model | Latency | Cost |
|---|---|---:|---:|
| Source mockup | (existing PNG, no gen) | 0 s | $0.00 |
| Decompose | claude-opus-4-1 | 75 s | $0.37 |
| Render | Playwright chromium | 1.3 s | $0.00 |
| Judge | claude-sonnet-4-5 | 18 s | $0.026 |
| **Total** | | **~94 s** | **$0.40** |

Result:
- **parityScore = 0.92**, status = `needs_review`, 11/12 checks passed (one iter, threshold 0.85)
- Judge summary: "The candidate closely matches the source design with proper layout, color scheme, and component structure. One minor gap is the truncated input placeholder text."
- Failed check: `content.text_labels_present` — *"Candidate's input field shows truncated placeholder 'describe the UI, or just uplo' instead of full 'describe the UI. or just upload a sketch...'"*

What the failure actually means: the second decompose pass's emitted ui_kit contained a truncated placeholder string. The live swapped UI in our `dist/` renders the placeholder correctly (verified visually in the AFTER source PNG) — the truncation lives in the model's NEW code emission, not our deployed app. Same class of model artifact as the `C&b` drift in the BEFORE pass.

This is the boolean rubric working as designed: one failed content check honestly flipped status from `verified` to `needs_review`, no fudging. A floating-point judge that averaged "everything else looked great" might have rounded this up. Our derived `passCount / totalChecks = 11/12 = 0.92` doesn't.

## What this proves

1. **The pipeline works**: brief → mockup → decomposed bundle → rendered → judged, end-to-end, both as a CLI (`scripts/career/poc-headless-pipeline/src/endToEnd.ts`) and as Convex actions (`convex/generation.ts`). Same shape, same prompts, same boolean rubric.
2. **The output is shippable**: the BEFORE pass's emitted CSS + DOM became the actual production UI of this repo. Not a side artifact.
3. **The verifier is honest**: the AFTER pass found one real drift instead of rubber-stamping its own output. A self-confirming rubric would have returned 1.00 again.
4. **Recursive stability holds at the 92% level**: when the platform looks at itself, it produces an output that closely matches itself, with deviations attributable to specific tokenization artifacts the boolean rubric correctly surfaces.

## What this does NOT prove

- That the visual judge alone is enough. It missed the `C&b` artifact in pass 1 because no content check was specifically required for that string. The deterministic text-coverage check in `convex/lib/parityChecker.ts` catches that class. We need both.
- That the pipeline is production-cost-efficient yet. $0.40-$0.43 per full run is fine for proof; it scales linearly with iter count, decompose model size, and judge model size. Cheaper-tier runs (Kimi K2.6 + Gemini Flash) cost ~$0.05-0.10 but trade off parity score (see `BENCHMARKS.md` once we port it from `feat/decompose-to-ui-kit`).
- That the platform can recover from large parity drops yet. The iterate stage is a v0.0.2 placeholder; a true gap-driven re-decompose with feedback loop is v0.0.3.

## Reproduce

```bash
cd scripts/career/poc-headless-pipeline

# BEFORE pass: prompt brief -> gpt-image -> ui_kit -> rendered -> judged
npm run e2e -- \
  --promptFile inputs/prompts/parity-studio-shell.txt \
  --decomposeModel claude-opus-4-1 \
  --judgeModel claude-sonnet-4-5 \
  --maxIters 2 --imageQuality high --imageSize 1536x1024 \
  --outDir runs/parity-studio-before

# AFTER pass: live UI screenshot -> ui_kit -> rendered -> judged
cd ../../parity-studio && pnpm build
cd dist && python -m http.server 5183 &
cd ..
npx tsx ../cafecorner_nodebench/nodebench_ai4/nodebench-ai/scripts/career/poc-headless-pipeline/src/captureLiveUrl.ts \
  http://127.0.0.1:5183 runs/after-source.png

cd ../cafecorner_nodebench/nodebench_ai4/nodebench-ai/scripts/career/poc-headless-pipeline
DECOMPOSE_MODEL=claude-opus-4-1 JUDGE_MODEL=claude-sonnet-4-5 \
  OUT_DIR=runs/parity-studio-after \
  npx tsx src/pipeline.ts --input ../../../parity-studio/runs/after-source.png
```

Set `ANTHROPIC_API_KEY` and `OPENAI_API_KEY` in your shell first. Total cost reproducing both passes: ~$0.50-$0.85 depending on whether the gpt-image source is cached.
