# Anonymized dogfooding notes

These are internal product-feedback notes from repeated NodeSlide dogfooding sessions. They are not paid-customer testimonials and must not be presented as commercial traction.

- A first-time user should land on one obvious composer, not a preloaded editor, setup dialog, or route full of internal parameters.
- The model and provider must be visible and selectable, but advanced controls must not compete with the typing area.
- Reasoning effort must use the provider's real vocabulary and supported values rather than a made-up universal scale.
- Files should attach through click, paste, or drag-and-drop and remain attached when the user briefly switches tabs.
- Web access and external-model egress must be stated separately and require explicit consent.
- A user should be able to ask for one-element, one-slide, selected-multi-slide, or whole-deck changes without granting a broader scope than necessary.
- AI edits should appear as a before/after proposal. Nothing canonical changes until the user accepts.
- The activity view should remain conversational; the deep trace should compress hundreds of spans into a searchable waterfall with real timestamps, cost, tool state, and source bindings.
- Source evidence should answer which claim or element it supports, not merely list URLs used somewhere in the run.
- The final workflow must include presenter mode and an editable PowerPoint export, not only static slide images.
