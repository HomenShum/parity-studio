# Canonical ui_kit zip — the import / export contract

Parity Studio's drop-zip importer and Export-ZIP endpoint share one
shape: the **NodeBench AI Skill-pack format**. This is the same shape
Anthropic Claude Code Skills consume, so a kit you export here is
loadable as a Claude Skill without further conversion.

A canonical zip looks like this:

```
<root>/
├── README.md                    # kit-level brand narrative + usage
├── SKILL.md                     # Claude Skill descriptor (frontmatter)
├── AGENTS.md                    # Codex/Cursor/Windsurf agent rules
├── .claude/skills/<slug>/SKILL.md
├── .cursor/rules/<slug>-parity-studio.mdc
├── colors_and_type.css          # shared brand tokens (source of truth)
├── assets/                      # SVG logos, webp hero/og, mask icons
├── preview/                     # one HTML specimen per token / component
├── explorations/                # WIP layouts (optional)
├── scraps/                      # working PNGs (optional)
├── screenshots/                 # final composed screenshots (optional)
├── uploads/                     # original source PNGs that fed the kit
└── ui_kits/
    ├── <slug-1>/                # one product per slug
    │   ├── index.html
    │   ├── components/*.tsx     # or *.jsx — drop-in components
    │   ├── tokens.css           # per-kit overrides over colors_and_type.css
    │   ├── manifest.json        # schemaVersion + slug + index path
    │   ├── parity.contract.json # operating contract for intent/perf/API/QA/privacy
    │   ├── performance.budget.json
    │   ├── api-wiring.plan.md
    │   ├── qa.plan.md
    │   ├── README.md            # per-kit handoff instructions
    │   └── HANDOFF.md           # generated by parity-studio export
    ├── <slug-2>/
    └── ...
```

## Required vs optional

| Path | Required? | Importer behavior | Exporter behavior |
|---|---|---|---|
| `README.md` (root) | optional on import, **emitted** on export | If present, the SKILL.md description seeds the run prompt | Auto-generated kit-level brand narrative + run telemetry |
| `SKILL.md` | optional on import, **emitted** on export | `description:` field becomes the run prompt for provenance | Auto-generated frontmatter pointing at the active slug |
| `AGENTS.md` | optional on import, **emitted** on export | Ignored | Shared instructions for Codex, Cursor, Windsurf, and other coding agents |
| `.claude/skills/<slug>/SKILL.md` | optional on import, **emitted** on export | Ignored | Project-local Claude Skill for integrating/iterating this slug |
| `.cursor/rules/<slug>-parity-studio.mdc` | optional on import, **emitted** on export | Ignored | Cursor rule that points agents at the operating contract |
| `colors_and_type.css` | optional, **emitted** on export | Read but not yet merged into the active run | Stub that imports `ui_kits/<slug>/tokens.css` so consumers have a single root token entry |
| `ui_kits/<slug>/...` | **required on import** | Parsed, the largest slug becomes the active run; other slugs are noted but not run | One slug per run (the latest ui_kit produced) |
| `ui_kits/<slug>/parity.contract.json` | optional on import, **emitted** on export | Backfilled if missing | Versioned operating contract: source, intent, appearance, organization, performance, API, QA, agent policy, BYOK/privacy |
| `ui_kits/<slug>/performance.budget.json` | optional on import, **emitted** on export | Backfilled if missing | Route/interaction budgets derived from the product performance principles |
| `ui_kits/<slug>/api-wiring.plan.md` | optional on import, **emitted** on export | Backfilled if missing | Plan-first live API wiring checklist and side-effect policy |
| `ui_kits/<slug>/qa.plan.md` | optional on import, **emitted** on export | Backfilled if missing | Browser routes, selectors, screenshots, console budget, overflow, and dogfood checks |
| `assets/logo-mark.svg` | optional, **emitted** on export | Ignored | Auto-generated terracotta P-mark with the slug's first initial |
| `assets/og-<slug>.svg` | optional, **emitted** on export | Ignored | Auto-generated 1200×630 OpenGraph card with slug, prompt, parity score, cost |
| `assets/README.md` | optional, **emitted** on export | Ignored | Documents how to extend assets/ with real brand artifacts |
| `preview/_shell.css` | optional, **emitted** on export | Ignored | Shared shell for specimen pages (pulls in `colors_and_type.css`) |
| `preview/index.html` | optional, **emitted** on export | Ignored | Specimen index linking every token + component preview |
| `preview/component-<slug>.html` | optional, **emitted** on export (one per `.tsx`/`.jsx`) | Ignored | Per-component specimen page with the component's source in a code block |
| `preview/tokens-{color,spacing,radius,typography}.html` | optional, **emitted** on export | Ignored | Auto-generated specimen pages parsed from `tokens.css` (color swatches, key/value lists) |
| `explorations/iter-<N>.html` | optional, **emitted** on export | Ignored | One file per artifact iteration so a recipient can diff the run's history |
| `explorations/README.md` | optional, **emitted** on export | Ignored | Describes the iteration history with per-iteration byte counts |
| `screenshots/source.<ext>` | optional, **emitted** on export when source image is present | Ignored | Mirrors `uploads/` source for visual handoff |
| `screenshots/README.md` | optional, **emitted** on export | Ignored | Documents the headless-render hook point (future visual verifier) |
| `scraps/README.md` | optional, **emitted** on export | Ignored | Documents the working-PNGs convention (future intermediate-state capture) |
| `uploads/<*.png\|jpg\|webp>` | optional | First image ≤ 2 MB becomes the run's `sourceImageBase64` for the source-image popover | The original source image is exported back here |

## Multi-slug zips

The canonical NodeBench zip ships **multiple slugs** in `ui_kits/`
(`nodebench-web`, `nodebench-mobile`, `nodebench-workspace`,
`nodebench-mcp`). The importer:

1. Picks the slug with the **most files** as the active run.
2. Notes the remaining slugs in the composer status line — they are
   preserved upstream (in the user's filesystem) but parity-studio
   only carries one slug per run today.
3. Future work: a follow-up could let the user pick which slug to
   activate, or split a multi-slug zip into N runs. Not done yet.

## Why symmetric?

If the way IN matches the way OUT, you can:

- **Round-trip**: export → unzip → re-import without information loss.
- **Library**: keep a folder of canonical zips (NodeBench, your own
  brand, a partner's) and drop them onto parity-studio to start a run
  pre-populated.
- **Skill compose**: an exported zip drops directly into Claude
  Code's `.claude/skills/` directory and becomes a self-describing
  Skill.

## File caps (importer)

To keep a run row sane:

- **Total zip size**: ≤ 30 MB
- **Per-file size inside the kit**: ≤ 200 KB (matches `patchFile`)
- **Source image inside `uploads/`**: ≤ 2 MB (matches `runs.start`)

Files above these caps are silently skipped on import; the user gets
a status line listing what landed.
